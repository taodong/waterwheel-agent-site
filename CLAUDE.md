## Project Purpose

A Docusaurus site for presenting documentation for the Waterwheel front-end testing AI agent. All content displayed on the site is in Markdown format.

## Technology

- Docusaurus with TypeScript

## Commands

Once the Docusaurus scaffold exists (`package.json` is present), use:

```bash
npm install          # install dependencies
npm start            # start local dev server (hot reload)
npm run build        # production build
npm run typecheck    # TypeScript type check
```

To run a single specific test (if tests are added):
```bash
npx jest <test-file-path>
```

## Architecture

- All site content lives in Markdown files under `docs/` (standard Docusaurus convention), grouped into five category folders:
  - `getting-started/` — the tutorial path, read in order
  - `guides/` — task-oriented how-tos
  - `reference/` — look-up material (test format, config files, commands, env vars, providers)
  - `how-it-works/` — permissions, MCPs, benchmarks
  - `about/` — release notes, support, license
- Static assets (icons, favicons) are in `static/img/`
  - `waterwheel_128.png` — logo
  - `waterwheel_favicon.ico`, `waterwheel_favicon_16.png`, `waterwheel_favicon_32.png` — favicons
- Docusaurus configuration lives in `docusaurus.config.ts`
- Sidebar structure is defined in `sidebars.ts`. It is fully autogenerated from the
  folder tree — category labels, order, and index pages come from each folder's
  `_category_.json`, and page order within a category from `sidebar_position` front matter.
- Cross-document links use folder-relative paths **with** the file extension
  (e.g. `[Command Reference](../reference/usage.mdx#run-qa-command)`) so that
  `onBrokenLinks: 'throw'` validates them at build time.
- Moving or renaming a doc changes its URL. Add the old → new pair to the
  `@docusaurus/plugin-client-redirects` `redirects` array in `docusaurus.config.ts`.
  Redirect stubs are emitted by `npm run build` only — they 404 under `npm start`.
