# Release Notes

The Waterwheel agent is distributed as a pre-built Docker image, free to use.

**Docker image:** [taojdcn/duotail-waterwheel](https://hub.docker.com/r/taojdcn/duotail-waterwheel)

:::tip[Use the latest release]
We recommend always running the latest version, **`1.5.0`**.

```shell
docker pull taojdcn/duotail-waterwheel:1.5.0
```
:::

## 1.5.0 — latest

The current release. It adds **reruns** — replay a chosen subset of tasks instead of the
whole suite, each one seeded from the context it had during the last full run. A test that
depends on an account registered earlier in the suite can now be replayed on its own,
which turns verifying one fix from a full-suite run into a run of a single task.

- **Context checkpoints** — every `run-qa` run writes a checkpoint to
  `/agent/outputs/checkpoints/<task-id>.json` immediately before each task runs. A rerun
  restores one of them — the checkpoint of whichever replayed task ran earliest in that full
  run — and executes its tasks against it, so a replayed task starts from the state the full
  run had reached by that point. The next full run clears them, so checkpoints always belong
  to the most recent run.
- **`rerun-config.json`** — a new instruction file naming the tasks to replay (`flow`),
  with an optional output folder `name` and optional `data` overrides. Write it by hand or
  have [`generate-rerun-config`](../reference/usage.mdx#generate-rerun-config-command)
  compose it. See
  [Configuration Files](../reference/configuration-files.mdx#rerun-configjson); its
  location is configurable with
  [`RERUN_CONFIG_PATH`](../reference/env-vars-reference.md).
- **Isolated rerun output** — unlike `run-qa`, a rerun never clears `/agent/outputs`. Each
  invocation writes to its own `outputs/rerun-<name>/` folder and leaves the original run's
  results untouched.
- **`--rerun` selector on the reader commands** —
  [`check-test-result`](../reference/usage.mdx#check-test-result-command),
  [`get-failure-detail`](../reference/usage.mdx#get-failure-detail-command), and
  [`output-context-variables`](../reference/usage.mdx#output-context-variables-command) now
  accept `-r` / `--rerun [name]` to read a rerun's folder instead of the full run's. With
  no name they read the most recent rerun; a mistyped selector is rejected rather than
  quietly answered with the full run's results.
- **Safer session tracking** — `run-qa` and `rerun-tests` share one single-instance lock
  and one session record, so they can never run at the same time, and each command names
  the stop command for whichever session is active. Recorded process IDs are validated by
  their start time before a stopper acts on them, so a stale record is discarded instead.
- **New commands:**
  - [`rerun-tests`](../reference/usage.mdx#rerun-tests-command) — replay the tasks named in
    `rerun-config.json`, seeded from the last full run's checkpoints.
  - [`stop-rerun`](../reference/usage.mdx#stop-rerun-command) — stop an active rerun. It
    refuses to terminate a `run-qa` session; stopping that one remains
    [`stop-qa`](../reference/usage.mdx#stop-qa-command)'s job, and `stop-qa` is still the
    universal stopper and the only stale-lock recovery command.
  - [`get-test-report`](../reference/usage.mdx#get-test-report-command) — report the full run
    and every rerun under it as a single JSON document. The `--rerun` selector above answers
    "how did *this* rerun go?"; this answers "what has been run at all?", which nothing else
    in the container could tell you — each rerun is keyed by the same name `--rerun` accepts.
    Two flags emit stripped-down projections for a code agent assembling a `rerun-config.json`:
    `--list-tests` gives each test's name and file, and `--list-results` gives how the run and
    each rerun ended. Its stdout is always JSON, with every diagnostic on stderr.
  - [`generate-rerun-config`](../reference/usage.mdx#generate-rerun-config-command) — compose a
    `rerun-config.json` document on stdout and pipe it to
    [`upload-instruction-file`](../reference/usage.mdx#upload-instruction-file-command); it writes
    nothing to disk itself. It is the write-side counterpart to `get-test-report --list-tests`:
    every task filename is checked against `/agent/tasks` and the `--name` rules are the agent's
    own, so an unknown file, an illegal name, or an occupied output folder is caught *before*
    `rerun-tests` starts the virtual display and both MCP services. `upload-instruction-file` now
    also rejects empty stdin, so a generation that fails mid-pipeline cannot blank a working
    config.

```shell
docker pull taojdcn/duotail-waterwheel:1.5.0
```

## 1.4.0

Adds **test skills** — reusable Markdown instructions the agent
loads on demand — so a tricky interaction is described once and a repeated flow such as
login is shared across tests without copying prose. See the new
[Create Test Skills](../getting-started/create-test-skills.mdx) guide.

- **Test skills** — a skill is a folder holding a single `SKILL.md` (front-matter `name`
  and `description`, then a Markdown body). The agent sees only the name and description
  while it decides whether a skill applies, and loads the full body only when it does, so
  a long skill costs nothing until it is used.
- **Built-in skills** — three ship inside the image under the reserved `ww:` prefix, each
  covering an interaction the raw browser tooling handles poorly on its own:
  `ww:clipboard-capture`, `ww:form-and-dialog`, and `ww:take-browser-screenshot`. The
  `ww:` prefix is reserved, so your own skill names can never collide with a shipped one.
- **`SKILLS_DIR`** — user skills are read from `/agent/skills` by default; point
  [`SKILLS_DIR`](../reference/env-vars-reference.md) at another folder to swap skill
  implementations per environment without editing a single test. Built-in skills are
  unaffected by it.
- **New commands:**
  - [`load-test-skills`](../reference/usage.mdx#load-test-skills-command) — create or, with
    `--force`, replace a skill from piped content.
  - [`display-test-skills`](../reference/usage.mdx#display-test-skills-command) — list every
    built-in and user skill, or print one skill's `SKILL.md` with `--show`.
  - [`delete-test-skills`](../reference/usage.mdx#delete-test-skills-command) — remove user
    skills by name (`-n`) or clear all of them (`-a`); built-in skills are never touched.
  - [`delete-builtin-skills`](../reference/usage.mdx#delete-builtin-skills-command) — remove a
    shipped skill by exact name. There is deliberately no `-a`, and the only way back is
    recreating the container.
- **Agent loops support** — the `waterwheel-load-test-skills`
  [Waterwheel skill](../guides/agent-loops.mdx) loads a project's test skills into the
  container as part of the pipeline. It requires this release; toolkit `v2.0.0` and newer
  pin agent image `1.4.0`.

```shell
docker pull taojdcn/duotail-waterwheel:1.4.0
```

## 1.3.0

Makes every part of the agent scriptable and introduces the
[Waterwheel skills](../guides/agent-loops.mdx) for pairing the agent with a code agent in a
nested test-and-fix loop.

- **Agent loops & skills** — a set of Claude Code skills that install, configure, and
  drive the agent automatically, enabling an autonomous, test-driven web development
  workflow. See the new [Agent Loops](../guides/agent-loops.mdx) guide.
- **Non-interactive setup** — configure the agent from scripts and CI without the
  interactive prompts of `config-agent`:
  - [`config-ai-provider`](../reference/usage.mdx#config-ai-provider-command) — apply an AI provider
    and model directly.
  - [`set-domain-permission`](../reference/usage.mdx#set-domain-permission-command) — generate the
    browser domain allowlist from a comma-delimited list.
  - [`enable-test-on-host`](../reference/usage.mdx#enable-test-on-host-command) — enable testing
    against a web app deployed on the host machine.
  - [`display-ai-config`](../reference/usage.mdx#display-ai-config-command) — print the effective
    provider, model, and token mode as JSON.
- **Programmatic test & instruction management:**
  - [`upload-test-task`](../reference/usage.mdx#upload-test-task-command) and
    [`upload-instruction-file`](../reference/usage.mdx#upload-instruction-file-command) — create or
    replace markdown tasks and instruction/config files from stdin.
  - [`reset-test-config`](../reference/usage.mdx#reset-test-config-command) — delete test tasks
    and/or instruction files to return to a clean state.
  - [`output-context-variables`](../reference/usage.mdx#output-context-variables-command) — export
    context values produced by the latest run as flat JSON for reuse outside the
    container.

```shell
docker pull taojdcn/duotail-waterwheel:1.3.0
```

## 1.2.0

Builds on `1.1.0` with richer test configuration and new helper commands.

- **`preset-context.json`** — a single file to manage per-run context variables
  and to configure the **test flow** (execution order and dependencies between
  tasks).
- **New commands:**
  - [`manage-test-files`](../reference/usage.mdx#manage-test-files-command) — add, list, and
    remove the markdown task files the agent runs.
  - [`preset-context`](../reference/usage.mdx#preset-context-command) — manage the context
    variables and test flow stored in `preset-context.json`.

```shell
docker pull taojdcn/duotail-waterwheel:1.2.0
```

## 1.1.0

Added multi-platform support and the first set of command-line tools.

- **Multi-platform images** — published for both `linux/amd64` and `linux/arm64`.
- **New commands:**
  - [`stop-qa`](../reference/usage.mdx#stop-qa-command) — stop the current QA run.
  - [`check-test-result`](../reference/usage.mdx#check-test-result-command) — check the latest
    test results.
  - [`get-failure-detail`](../reference/usage.mdx#get-failure-detail-command) — print a
    diagnostic report for the first failed test.
  - [`config-agent`](../reference/usage.mdx#config-agent-command) — configure the AI provider,
    browser permissions, and access to a test website on the host.
  - [`manage-global-constants`](../reference/usage.mdx#manage-global-constants-command) — manage
    global constants shared across all tests.
  - `manage-context-variables` — manage per-run context variable overrides.
    *(Replaced by [`preset-context`](../reference/usage.mdx#preset-context-command) in 1.2.0.)*
