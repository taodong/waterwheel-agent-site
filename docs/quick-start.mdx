This is a quick guide to get the Waterwheel agent running on your local machine and execute a sample QA task. The
steps below cover **macOS / Linux**, **Windows (PowerShell)**, and
**Windows (CMD)**. Use the tabs to pick your shell.

:::info[Once you're inside the container, the OS no longer matters]
Only the host-side setup steps (setting environment variables and `docker run`)
differ between operating systems. Commands such as `config-agent`,
`manage-test-files`, `run-qa`, and `check-test-result` are run through
`docker exec` and are **identical on every platform**, so those steps are shown
as a single code block.
:::

## Prerequisites

### Docker Desktop Application
Install **Docker Desktop** for your machine from
[docker.com/get-started](https://www.docker.com/get-started/) and make sure it is
running before you continue.

### AI API Key
The agent must connect to an LLM to perform QA tasks, so you need to provide your own AI API key.
Currently supported AI providers include `Anthropic`, `OpenAI`, `Gemini`, `DeepSeek` and Ollma hosted `Gemma 4`.

:::note[Gemma 4 Support]
For simple QA tasks, you can use `Ollama`-hosted `Gemma 4`.
When using `Gemma 4`, you can use any non-empty text as the API key.
:::

## 1. Set Your API Key

Export your AI provider API key into the current shell session. The optional
second line silences Docker's CLI hint messages.

<Tabs groupId="os">
<TabItem value="unix" label="macOS / Linux" default>

```bash
# Required: your AI provider API key
export AI_API_KEY=your_api_key_here

# Optional: silence Docker CLI hint messages
export DOCKER_CLI_HINTS=false
```

</TabItem>
<TabItem value="powershell" label="Windows (PowerShell)">

```powershell
# Required: your AI provider API key
$env:AI_API_KEY = "your_api_key_here"

# Optional: silence Docker CLI hint messages
$env:DOCKER_CLI_HINTS = "false"
```

</TabItem>
<TabItem value="cmd" label="Windows (CMD)">

```bat
:: Required: your AI provider API key
set AI_API_KEY=your_api_key_here

:: Optional: silence Docker CLI hint messages
set DOCKER_CLI_HINTS=false
```

</TabItem>
</Tabs>

:::note[Session Scope]
These variables live only in the terminal window where you set them. Run the
`docker run` command in **step 2** from the **same** terminal so the key is
available to the container.
:::

## 2. Install the Waterwheel Container

This pulls the image (on first run) and starts the agent in the background. It
mounts two folders from your current directory: `tasks` for the QA task files you
want the agent to run, and `outputs` where results and logs are written.

<Tabs groupId="os">
<TabItem value="unix" label="macOS / Linux" default>

```bash
docker run -d --name waterwheel-agent \
  -v "$(pwd)/tasks":/agent/tasks \
  -v "$(pwd)/outputs":/agent/outputs \
  -e AI_API_KEY \
  taojdcn/duotail-waterwheel:1.2.0
```

</TabItem>
<TabItem value="powershell" label="Windows (PowerShell)">

```powershell
docker run -d --name waterwheel-agent `
  -v "${PWD}/tasks:/agent/tasks" `
  -v "${PWD}/outputs:/agent/outputs" `
  -e AI_API_KEY `
  taojdcn/duotail-waterwheel:1.2.0
```

</TabItem>
<TabItem value="cmd" label="Windows (CMD)">

```bat
docker run -d --name waterwheel-agent ^
  -v "%cd%/tasks:/agent/tasks" ^
  -v "%cd%/outputs:/agent/outputs" ^
  -e AI_API_KEY ^
  taojdcn/duotail-waterwheel:1.2.0
```

</TabItem>
</Tabs>

:::tip[Volume mounts on Windows]
Docker Desktop's WSL 2 backend handles `${PWD}` (PowerShell) and `%cd%` (CMD)
automatically. If a volume fails to mount, confirm that your drive is shared
under **Docker Desktop → Settings → Resources → File sharing**.
:::

## 3. Configure the Agent

Launch the interactive configuration script. It walks you through choosing an AI
provider mode.

```bash
docker exec -it waterwheel-agent config-agent
```

:::warning[The AI provider is locked once set]
After you save a provider mode, switching to a **different** provider (for
example Anthropic → DeepSeek) requires creating a new container. You can still
switch between modes of the same provider at any time. See the
[Provider Configuration Guide](./provider-guide) for recommended provider settings.
:::

## 4. Add a Sample Test

Download the sample test into the `tasks` folder next to where you ran
`docker run`:

<a href="/files/installation/test-wikipedia-english.md" download>test-wikipedia-english.md</a>

This sample verifies that clicking the `English` language link on
[wikipedia.org](https://www.wikipedia.org) navigates to the English welcome page.

Because `tasks` is mounted into the container, the file is available immediately.
Confirm the agent sees it:

```bash
docker exec -it waterwheel-agent manage-test-files list
```

The `list` command should show `test-wikipedia-english.md`.

:::tip[Managing tasks later]
Drop more `.md` files into your `tasks` folder to add them, or remove files from
it to drop them. You can also manage tasks with `manage-test-files add`,
`manage-test-files delete`, and `manage-test-files clear`. See the
[Usage](./usage#manage-test-files-command) guide for the full command reference.
:::

## 5. Verify Your Configuration

Run a dry run first to confirm everything is wired up correctly without consuming tokens.

```bash
docker exec -it waterwheel-agent run-qa --dry-run
```

## 6. Run Your QA Tasks

When the dry run looks good, execute the tests in the `tasks` directory, which contains the sample test from step 4.

```bash
docker exec -it waterwheel-agent run-qa
```

## 7. Check the Results

Print the contents of the latest test results.

```bash
docker exec -it waterwheel-agent check-test-result
```

:::tip[Investigating a failure]
For a detailed diagnostic report of the first failed test — including the test
steps, agent log, and context — use:

```bash
docker exec -it waterwheel-agent get-failure-detail
```
:::

## Uninstallation

If you need to change your AI provider, uninstall the agent and reconfigure it from step 1. Your `tasks` and `outputs`
folders on the host are untouched.

```bash
docker rm -f waterwheel-agent
```
